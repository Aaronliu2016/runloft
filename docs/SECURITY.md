# 安全模型

RunLoft 会启动来自 Git 仓库的程序，并在本机显示其 Web 页面。仓库代码和配置都应视为不可信输入，直到用户完成审查。下载公开仓库不代表用户已经授权执行其代码。

## 1. 信任与命令执行

- clone/fetch 与执行命令是不同操作；第一次 prepare/start 前展示将运行的命令、参数、工作目录，以及子进程继承当前 RunLoft 进程环境这一事实。预览只列出名称匹配敏感字段规则的环境变量并隐藏值；不会逐项列出其余环境变量。
- 项目运行配置保存在 RunLoft 应用数据，不写入目标仓库。prepare/start 与 Git 更新都要求 Git 工作区干净。授权摘要绑定仓库身份、当前 Git commit 和解析后的应用内配置；确认后会再次校验提交、配置和工作区状态，任一变化都会取消执行。
- Git 忽略的文件（例如依赖安装目录或构建产物）不在干净状态检查和授权摘要内；经授权运行的目标程序可以访问工作区文件。
- 子进程继承的环境不属于授权摘要，在 RunLoft 外部变化不会使既有授权失效；运行不可信仓库时，不要让 RunLoft 继承不应交给目标程序的秘密。
- prepare/start 授权对话框前会运行配置声明的运行时版本探针；探针只使用代码内置的命令白名单和固定参数，实际可执行文件由本机 `PATH` 解析。项目配置不能指定任意诊断命令或参数。
- 使用参数数组直接启动进程，不默认经由 shell；不支持隐式管道、重定向或命令替换。
- 工作目录限制在仓库内；不把仓库路径、配置字段直接拼进 shell 命令。
- `prepare` 步骤只能由用户主动触发；不得因 clone 或启动应用而静默执行。整组步骤须按序运行，失败后停止且不自动重试。
- MVP 不自动安装或更新 Node.js 等运行时；目标项目依赖仍通过经用户审查授权的准备步骤处理。
- 日志需对令牌、口令和已知敏感环境变量做遮盖；避免将完整进程环境写入日志。

## 2. Git 和本地数据保护

- 仅在用户主动检查更新时执行 fetch；只有用户明确确认后才应用快进更新。
- 更新前检查工作区状态；有未提交改动、未跟踪文件或分支分叉时阻止更新。
- 不使用会丢弃用户工作的 reset/clean 操作，也不自动 stash/pop。
- Git 命令使用 RunLoft 创建的空 hooks 目录，避免调用仓库本地 hooks。
- 用户明确移除项目时说明代码工作区和 RunLoft 元数据的影响；默认不递归删除工作区。
- 凭据委托给系统 Git credential helper 或 SSH agent；MVP 不在 RunLoft 数据库中保存访问令牌。

## 3. WebView 与本地服务

- 默认只加载绑定到 loopback 地址的项目服务。
- 校验 scheme、host、端口和重定向目标；拦截导航到远程站点、`file:` 和其他本地服务。
- 用户主动点击的跨域 HTTP(S) 链接经 URL 凭据校验、敏感查询参数和片段剥除后交给系统浏览器。`target="_blank"` / `window.open` 请求先显示原生确认框；非 HTTP(S) 或带 URL 凭据的请求直接阻止。
- 目标项目页面不获得 RunLoft 的 Go 绑定或特权 IPC。
- MyGo 目前没有可配置的按项目 WebView profile；RunLoft 在每次创建目标项目 WebView 前清除应用浏览数据，避免不同项目间共享 Cookie、localStorage 等。项目登录状态不会跨次运行保留。
- MVP 不承诺抵御已授权目标项目本身的恶意行为；用户授权后启动的程序仍可使用当前用户权限访问本机资源。

## 4. 进程和端口

- 服务应绑定 `127.0.0.1`，除非用户显式修改并确认配置。
- RunLoft 只向自己创建的进程组/Job Object 发出终止请求，不按端口号查杀其他程序。Unix 使用独立进程组；Windows 使用 Job Object，并以系统 `taskkill /T` 发起优雅停止。当前等待主进程退出，但不独立确认每个后代进程均已结束；目标 Windows 设备上的行为仍待验证。
- 端口冲突时不得把 WebView 导航到占用端口的其他服务；停止启动流程并提示处理。
- 关闭应用时会在限定时间内尝试优雅停止并强制清理；手动停止时主进程未退出会显示错误。应用退出路径目前忽略清理错误并继续退出，后代进程最终退出状态也不单独确认。

## 5. 需要验证的边界

- MyGo 页面导航回调在首发平台上是否足以实施上述 URL 策略；程序化入口 URL 必须在加载前单独校验。
- WebView 对 loopback 服务的 cookie、跨源请求、WebSocket 和隔离 profile 行为。
- macOS、Windows、Linux 上进程组创建和结束方式是否存在差异；当前 Windows 进程树清理没有目标设备实测。
- Git hooks、过滤器和仓库内容在克隆及更新路径中的执行边界；相关 Git 参数应在实现时逐项审查。

## 6. 安全验收

- 未经授权的命令不能启动；修改命令后旧授权失效。
- 工作区含有未提交或非忽略的未跟踪文件时，prepare/start 不会执行；项目配置保存在 RunLoft 应用数据中，不计入目标仓库状态。
- 目录穿越配置被拒绝。
- 非 loopback URL、恶意重定向和外链按预期拦截。
- 本地有改动时更新不会改变工作区内容。
- 停止一个项目不会终止其他项目或用户手工启动的进程。
- 日志中不出现配置的秘密值或完整环境转储。
