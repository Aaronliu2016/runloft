# RunLoft 项目方案

## 1. 项目定位

RunLoft 为“以本地 Web 服务交付、但没有独立桌面入口”的项目提供一个桌面启动与管理入口。用户在桌面应用中管理本地代码副本，RunLoft 按项目仓库声明的配置启动服务，并在桌面窗口中显示它。

产品名暂定为 **RunLoft**。命名、图标和正式品牌说明可以在首个可用原型之后确定。

## 2. 要解决的问题

一些 Web 项目目前需要用户打开终端、切换目录、安装依赖、执行启动命令，再通过浏览器访问本机端口。重复使用时，这些步骤容易出错；项目也缺少统一的启动、停止和更新入口。

RunLoft 负责把这些本地操作组织成一个可见、可控的桌面工作流。项目本身仍使用原有 Web 技术栈和服务端口，不要求为 RunLoft 改写完整前端。

## 3. 目标用户与主要场景

### 目标用户

- 需要反复使用一个或多个本地运行 Web 项目的个人用户。
- 希望将 Web 项目以桌面窗口方式打开，同时保留原仓库开发和更新方式的用户。
- 项目维护者：希望通过仓库中的简短配置声明推荐的安装、启动和就绪检查命令。

### 主要场景

用户添加仓库后，RunLoft 将项目克隆到本地；首次运行前展示仓库配置和将要执行的命令；用户确认后启动服务，等待健康检查成功，再将窗口导航到本地地址。之后用户可以停止项目或在工作区干净时获取更新。

## 4. 产品目标

1. 让用户无需手工查找项目目录和启动命令即可启动受支持的项目。
2. 在一个桌面窗口中显示项目本地服务，并清楚呈现启动、就绪、失败和停止状态。
3. 明确处理依赖安装、端口冲突、服务未就绪、启动失败和关闭清理。
4. 把仓库命令作为可审查的配置，在首次执行和配置改变后征求用户确认。
5. 保留用户的本地代码改动，避免更新操作静默覆盖工作区。
6. 通过可版本化的配置约定，让项目维护者能够描述项目如何在 RunLoft 中运行。

## 5. 非目标

- 不替代目标项目的包管理器、运行时、构建系统或开发服务器。
- 不重写或托管目标项目的 Web 前端。
- 初期不提供通用终端、IDE、代码编辑器、容器编排或云端构建平台。
- 初期不自动执行仓库中的安装或启动脚本，也不在更新时重置用户代码。
- 不承诺任意 Web 项目都能无配置运行；项目必须声明可执行命令和本地访问地址。

## 6. MVP 范围

### 必须具备

- 添加 Git 仓库和选择本地工作区。
- 克隆仓库；显示当前分支、提交和工作区变更状态。
- 读取并校验根目录 `.runloft.yaml`。
- 在命令执行前展示命令、工作目录及必要环境变量，并提供用户授权。
- 启动、停止一个项目进程；收集可查看的 stdout/stderr 日志。
- 对配置端口执行 HTTP 就绪检查；成功后在 MyGo 窗口的系统 WebView 中打开。
- 对缺少配置、运行时、依赖或 WebView 的情况给出明确错误。
- 仅在工作区干净时提供安全的快进更新；有本地变更时先停止并提示用户处理。

### 后续考虑

- 多项目并行运行、动态端口分配、系统托盘、通知、应用自动更新、导入已有目录、项目配置模板和更多运行时诊断。
- 是否支持私有仓库、凭据管理、跨设备同步和更多目标平台，应根据 MVP 使用情况另行决定。

## 7. 体验原则

- **操作可见：** 显示正在执行的步骤、服务地址、项目状态和日志入口。
- **先检查再执行：** 下载仓库不等同于信任其脚本；命令必须先预览再授权。
- **失败可恢复：** 保留日志和本地工作区，不通过删除或重置来掩盖启动问题。
- **贴近项目：** 启动行为由仓库配置描述，尽量调用项目原有工具链。
- **边界清楚：** 桌面壳处理项目管理与生命周期；网页继续由目标项目负责。

## 8. MVP 成功标准

- 对一个已验证的真实目标项目，首次克隆后能通过 RunLoft 完成依赖准备、启动、就绪检测、显示和停止。
- 端口占用、启动命令退出、健康检查超时和配置错误都能在 UI 中区分并保留有用日志。
- 用户修改工作区后，更新流程不会覆盖或丢弃改动。
- 未授权的配置命令不会执行；配置变更会重新触发审查。
- 在确定的首发平台上完成安装包验证，并记录 MyGo 与系统 WebView 的依赖。

## 9. 关键假设与待决事项

- “方案 B”按当前可读讨论理解为：桌面端负责本地仓库和进程生命周期，原 Web 项目继续以自己的本地服务运行，再由桌面窗口呈现。引用的历史助手长文在当前线程读取接口中仅显示引用标记，故本方案不猜测其中未显露的细节。
- 首发操作系统尚未从可读取的讨论内容中确认；P0 应选择开发验证平台，并记录后续平台支持矩阵。
- MyGo 文档说明其 WebView 使用系统 WebView，但将目标项目的 loopback 服务嵌入窗口以及安全导航策略仍需原型验证。
- 项目是否为目标项目安装或下载缺少的运行时尚未确定。MVP 可先依赖用户本机已安装的运行时，并在界面中提供诊断。
- `.runloft.yaml` 的最终字段、版本兼容策略和允许的命令表达能力需在配置原型评审后冻结。
